Offline-first is not a feature here. It is the baseline.

Tanvir Mahmud8 December 20256 min read

Building for intermittent connectivity changes your data model, not just your error handling. Better to decide that at the start.

A retail chain we built for has 118 outlets. On any given day, several of them will lose connectivity during trading hours. If the point of sale requires the network, those outlets stop selling — and the fix is not a better network contract.

Offline is a data model decision

Teams usually treat offline support as error handling: catch the failure, queue the request, retry later. That works until two devices modify the same record, or a price changes centrally while a terminal is disconnected, or a sync retries an operation that was not idempotent and charges a customer twice.

Real offline capability starts earlier, in how you identify and merge records. Client-generated identifiers, explicit versioning, and a documented conflict resolution rule per entity — decided by the business, not by whichever write arrives last.

  • Client-generated identifiers so records exist before the server sees them
  • Idempotency keys on every mutating operation, without exception
  • Per-entity conflict rules agreed with the business, written down
  • Explicit sync state visible in the interface — never a silent queue
  • Bounded local storage with a documented eviction policy
The question is never "what happens when the network fails". It is "what is true when two versions of reality meet".

Show the state, always

The interface must never lie about what has been saved. A cashier needs to see that a sale is recorded locally and not yet synced; a rider needs to know which deliveries have been confirmed centrally. A hidden queue produces a specific kind of failure — the confident user who finds out a day later that nothing was recorded.

Designed from the start, offline capability costs perhaps fifteen percent more engineering. Retrofitted, it usually costs a rewrite of the data layer. It is worth deciding in week one.
