A design system two designers can actually maintain

Mehedi Hasan11 March 20266 min read

Small teams are told design systems are a luxury for big companies. The opposite is true — you need one precisely because there are two of you.

There are two designers in this studio. We ship for clients in four markets. The only way that arithmetic works is that we do not redraw a date picker every time a project starts.

Build the system out of real projects

We did not sit down and design a system. We built three client projects, noticed which components we had rebuilt three times, and promoted exactly those into a shared library. Everything else stayed in its project where it belongs.

That order matters. A system designed in the abstract is a guess about what you will need. A system extracted from delivered work is evidence.

Promote a component on its third appearance, not its first. Two uses is a coincidence; three is a pattern.

One name, three places

A component must carry the same name in the design file, the code library and the documentation. It sounds trivial. For a studio where the designer also writes the front-end, it is the difference between one afternoon and three.

  • Tokens generated from one source into both the design tool and the CSS
  • Identical component names across design, code and documentation
  • Every component documented with states, do-and-don’t and accessibility notes
  • A per-client theme layer, so one system serves every brand we work with
  • A deprecation policy, because a system that cannot remove things becomes the problem

The client has to be able to keep it

The system we hand over is not ours — it is theirs, and usually it will be maintained by one person who has never built a design system before. So the documentation is written for that person: what each component is for, when not to use it, and how to add a new one without breaking the tokens.

Across our first year, roughly seventy percent of the interface in a typical delivered project is rendered by system components. The remainder is genuinely bespoke, and forcing it into a general system would make both worse. Knowing which is which is the whole skill.
